Atlas Product Requirements

Atlas connects to a company's cloud (AWS, read-only) and code (GitHub / Bitbucket / Jira), builds a continuously-updated knowledge graph of their infrastructure, code, deployments, dependencies, and intent, and lets engineers understand it through a visual map, search, and a cited AI interface.

01Product in one sentence

Atlas turns a company's sprawl of cloud accounts, repositories, deploys, and tickets into one live, cited knowledge graph — then makes it usable through a visual map, search, and an AI interface that only ever answers from the graph.

The governing principle — P1: The knowledge graph is the product. The AI is the interface. Every requirement ladders back to graph correctness and trust, not chatbot polish.

02Who it's for

PersonaNeed Atlas serves
A — New / returning engineer“What do we run, and how does it fit together?” — onboard to an unfamiliar estate in minutes, not weeks.
B — On-call / incident responder“What broke, what's the blast radius, and which change caused it?” — trace an alarm to the service, deploy, and PR (the War Room).
C — Staff / platform engineer“Where are the risks and single points of failure?” — posture, sprawl, and toxic combinations across code + cloud.
D — Eng leader“Is our estate healthy, well-owned, and did we build what we said?” — health, ownership, activity, and PR-vs-intent coverage.
E — Security / compliance reviewer“Prove this is read-only, tenant-isolated, and controls-mapped.” — the security package: IAM design, RLS isolation, provenance, audit, DSAR.

03Product principles — the non-negotiables

P1Graph is the product

The AI is the interface. Effort goes to graph correctness and inference, not chatbot polish.

P2Read-only by construction

No code path can mutate a customer's cloud or repo — enforced at the IAM/App-permission layer. Zero mutating SDK calls exist in the connectors.

P3Missing edge > wrong edge

High precision over recall; ambiguity yields multiple low-confidence edges, never one wrong high-confidence one.

P4Provenance on everything

No un-sourced edges; every AI claim cites a real node or edge.

Trustis visible

Observed / inferred / stale / manual are distinct states. “I don't know” is a designed answer, never a fabrication.

R8Tenant isolation is existential

Every path is org-scoped (restricted role + composite FKs + Postgres RLS). Cross-tenant access returns 404, never 403.

04Current features — shipped

Live on real data Code-complete · pending creds Built & tested in-repo
4.1

Platform & identity

LiveGoogle sign-in — Supabase-hosted OAuth; Atlas verifies the ES256 JWT via JWKS and mints no tokens.
LiveOrganizations, roles & RBAC — Owner > Admin > Member with last-Owner + Owner-only invariants; invite / revoke / role-change, all in Settings.
LiveTenant isolation — three layers (restricted atlas_app role + composite FKs + RLS GUC); cross-tenant → 404. A boot assertion refuses SUPERUSER/BYPASSRLS.
LiveGlobal authentication by default — every route needs a valid bearer token unless explicitly public (webhook / unsubscribe / health).
LiveAppend-only audit log — security-relevant mutations recorded to an org-scoped table; an admin Activity log in Settings.
LiveProfile + email preferences — edit name/avatar; per-workspace incident-alert & digest opt-outs.
4.2

Connectors & ingest

LiveAWS crawler (read-only) — AssumeRole + External ID or static keys; per-service permission probing → degraded with the exact missing IAM actions. ~150 resources on a real account.
LiveBitbucket connector — a real workspace end-to-end (60 repos, 155+ merged PRs, insights).
LiveJira connector — intent-field discovery + a reference-driven crawl (cost ∝ what the code references, not the whole backlog). 275 issues synced.
ReadyGitHub crawler — App auth, CODEOWNERS + manifest + workflow-deploy parsing, webhook HMAC. Code-complete; live verify pending an install.
LiveEncrypted secret store — AES-256-GCM, key from env (never in DB), fail-closed. Deleted on disconnect and org-delete.
LiveStaged, safe sync — plan → discover → normalize → persist → reconcile per scope in one transaction; partial-sync safety; orphaned-run reaper.
LiveSync visibility — live status, missing-permission hints, egress-IP allow-list note + unreachable-connection detection.
4.3

Knowledge graph, inference & manual curation

LiveGraph-shaped store — nodes + edges + provenance + snapshots + signals, dual UUID+URN identity; composite FKs make cross-tenant edges impossible.
LiveInference engine (R1–R18) — cross-source edges (deploys, connects, implements, owned-by, exposed-via…), convergent, retires-not-deletes, provenance on every edge.
LiveAI-assisted edge suggestions — the LLM proposes repo↔runtime links beyond deterministic matching, badged “AI-suggested”; confirm promotes, reject remembers.
LiveManual graph editing — hand-draw a missed link or remove a wrong one; manual edges are human-vouched, removals are remembered.
LiveConfidence & freshness — observed / inferred / ai-suggested / manual / stale, rendered distinctly.
LiveTraversals — bounded blast-radius + dependencies, each with a why-chain and a weakest-link path confidence.
4.4

AI — Ask Atlas

LiveGrounded, cited answers — retrieval-first RAG; every claim binds to a real node/edge citation (P4). Claude in prod, mock in dev/CI, per-org BYO-LLM key.
LiveAgentic tool-calling loop — bounded read-only tools (search, get_node, neighbors, blast-radius, diagnose, timeline, get_pr_diff) streamed over WebSocket, cancellable.
LiveHonest absence + grounding gate — ungrounded questions return a designed “I don't know”; deterministic citation + suppression gates; escaped-hallucination rate 0.
LiveAdvisory answers & memory — fact-vs-advice trust model; multi-turn context; a citation opens a resource peek drawer.
4.5

Product surfaces

LiveDashboard — estate-health ring, findings severity bar, source health, inventory, needs-attention rail, recent activity.
LiveInfrastructure Map — one left-to-right flow with Health / Changed / Exposed / Security lenses, blast-radius on click, an in-canvas cited AI chat, and manual linking.
LiveExplore — list-first browser with facets + Health column; answer-first node detail; a “why?” edge-evidence page.
LiveInsights — “Fix first” strip, posture bars, findings lifecycle (open / regressed / fixed), mute/accept, recheck, per-finding “ask how to fix”.
LiveIntegrations hub & Settings — connect/verify/sync/disconnect; org identity, members, BYO-LLM, alerts, email prefs, Privacy & data, audit log.
LiveOnboarding + motion system — “Load sample data” first-run; subtle, reduced-motion-safe animation throughout.
4.6

Operational intelligence — the north star

LiveHealth layer — ELB / ECS / RDS / CloudWatch + Lambda metric-health polled; unhealthy resources go red everywhere.
LiveChange timeline — deploys + config-changes + merged-PRs + alarm transitions unified for “what changed lately” + RCA.
LiveOne-click Diagnose — every degraded node runs the culprit-tracing loop → cited hypotheses + ranked verdict.
LiveWar Room — an incident page: live blast-radius map + streamed cited diagnosis + ranked cause, persisted to Insights and replayed on reopen.
LiveProactive notifications — in-app bell + Slack / Discord / Teams webhooks + daily digest, with per-user opt-outs.
4.7

Intent verification — spec → code

LivePR-implements-issue linking (R18 + fuzzy) — links PRs to the ticket they implement, by key and by a deterministic fuzzy matcher; ambiguity → nothing. 163 PRs linked.
LiveCoverage judge — an LLM judges, per acceptance criterion, whether the PR diff actually implements it, with a deterministic suppression gate.
4.8

Security, vulnerability & compliance intelligence

LiveDependency intelligence — manifest parsing → package nodes → OSV.dev enrichment → vulnerability findings + blast-radius + sprawl (cited, with guidance).
LiveCloud posture rules — open SGs, public-vs-name LB mismatch, single-AZ DBs, wildcard IAM, root-no-MFA, public buckets, unencrypted data.
LiveExposed-AND-vulnerable — the toxic combination across code + cloud: an internet-reachable service running a vulnerable dependency.
LiveCompliance monitor — technical-controls monitor across 6 frameworks (PCI / CIS / NIST / ISO / HIPAA / GDPR) with an honest “not assessable” state.
4.9

Privacy & data governance

LiveErasure on disconnect / org-delete — purges the subgraph + credential + raw snapshot blobs + Storage objects. No orphaned PII.
LiveRetention — a daily cross-org sweep purges aged rows + blobs (snapshots 30d, activity 365d, sync history 90d).
LiveDSAR — access + erasure — export the personal data Atlas holds; erase a person (durably re-applied after each sync). A Privacy & data settings card.
LiveSecrets & transport hardening — AES-GCM secrets, SSRF-safe webhooks, PII masked in logs, nonce CSP + HSTS, locked CORS, durable rate limiting.

Extensibility & quality

06Non-goals — deliberately out of scope

Not a mutation tool

Atlas never writes to a customer's cloud or repo (P2). No remediation actions, no IaC apply.

Not an APM / metrics store

It reads health signals to colour the graph; it is not a time-series monitoring product.

Not a chatbot

The AI is grounded in the graph and refuses beyond it; breadth is secondary to citation integrity.

Not a general search engine

Search is a projection over the graph, never a separate source of truth.
